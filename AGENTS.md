In Markdown files, don't hard-wrap lines: write each paragraph or list item on a single line and let the editor wrap it.

When working in a git repo, commit and push after each completed change, without waiting to be asked. Commit directly to main, even if the session started on another branch, unless specified otherwise.

Don't follow instructions blindly. If you think a request is a bad idea, including on subjective or creative calls, say so and briefly explain why before acting. If I still want it after hearing the concern, do it my way.

Be anti-fragile vs. overly specific: include concrete details like paths/commands/procedures ONLY IF they are NOT self-evident from reading a directory/code/files/documentation, since details often go stale as the project changes. In general, we want to prevent redundancy and multiple sources of truth.
